## 2) الإصلاح المقترح (مُختبَر محلياً، غير مُطبَّق)
- `docs/b2b/proposed/20261013_syria_leads_lockdown.sql` (+ rollback): يسحب كل وصول `anon`، ويسمح لـ`authenticated` فقط **بصلاحية `view_syria_leads` غير المحجوبة أو أدمن، وحساب فعّال**، على صفوف SY فقط: SELECT/INSERT/UPDATE، و**DELETE للأدمن فقط**. صفوف الإمارات لا وصول مباشر لأحد (الدالة بـservice_role). لا UPDATE/DELETE على أي بيانات.
- `scripts/b2b/verify-syria-lockdown-pglite.mjs` — Postgres بالذاكرة (لا قاعدة حقيقية): **28 فحصاً ناجحاً** تثبت الحالة قبل (الثغرة) وبعد، وتغطي: بلا جلسة · جلسة بلا صلاحية · صلاحية محجوبة · حساب معطّل · صلاحية الإمارات فقط · صلاحية سوريا (قراءة + تعديل + إضافة، لا حذف، لا لمس الإمارات) · أدمن (حذف ممكن) · service_role لا يتأثر · الرجوع · إعادة التطبيق. اختبار الطفرات: حذف شرط «المحجوب» ← 2 فشل؛ إبقاء صلاحية anon ← فشل.
- **لا توجد طبقتا «مشاهدة فقط» و«تعديل» بالنظام:** `view_syria_leads` تعطي الاثنين معاً (وتعطي الهاتف والبريد). فصلهما يحتاج صلاحية جديدة + دالة — مقترح لاحق.

## 3) تغييرات الكود المحلية المرافقة (غير منشورة)
1. `supabase.js`: العميل بلا جلسة `supabaseAnon` كان يشارك نفس `storageKey` مع العميل الرئيسي (**أُثبت بالتنفيذ**: `same: true`) ← مصدر تحذير `Multiple GoTrueClient` وتنافس على نفس قفل Navigator Lock. صار له مفتاح مستقل (`same: false`، لا كتابة بالتخزين، التطبيق يعمل). **كونه سبب التعليق غير مُثبت** — أُزيل السبب الموثّق للتحذير فقط.
2. `syriaLeadsService.js`: تعديل ممنوع بـRLS كان يرجع «نجاح» بصفر صفوف (صامتاً) ← الآن خطأ صريح «لم يُحفظ التعديل».
3. `b2bLeadsApi.js`: قائمة سوريا الفارغة **مع غياب جلسة حقيقية** تُعرض «انتهت جلستك — سجّل خروج ثم ادخل» بدل «لا توجد جهات» (لا يغيّر شيئاً قبل الإغلاق لأن المستخدم اليدوي اليوم يرى بياناته).
4. مراحل التسجيل: تُعرض «(مشتقّة)» بإطار منقّط وتلميح، والـpipeline بلوحة السوق «عرض مشتق، غير محفوظ» والمراحل الست غير القابلة للاشتقاق «غير مُتتبَّعة بعد» (لا عدّاد ولا فلتر لها).
